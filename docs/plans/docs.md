# 资料库页面变成大家一起写的文档

## 为什么

Bot 之间交接工作，常常要一份大家一起改的文档：一个查完资料写初稿，另一个接着改成周报，用户在中间批几句。
以前只能借 Notion（应用市场里的官方连接）：不是每个人都有、都想用 Notion 账号；几个 Bot 共用一个授权，分不出是谁写的；
在 Notion 里批注，Bot 不会知道；交接时下一个 Bot 还要再读一遍。

资料库本来就有页面，只是：只能整页覆盖，而且只有建它的 Bot 能改；人只能看；没有历史。这份计划把它变成 OSA 自带的文档：
Bot 能接着改同一份文档，人能像 Notion 一样直接编辑、批注，批注会叫醒负责的 Bot，每次修改都能回滚。

## 定下来的事

- **正文以 Markdown 为准**：页面正文只有一份 Markdown（`pages.content`），Bot 读写都是 Markdown。
  编辑器只提供 Markdown 存得下的格式：标题、列表、待办、表格、代码、引用、分割线、链接、图片，
  再加两种 Notion 常用的块：提示框（GitHub 的写法 `> [!NOTE]`）和折叠块（`<details>`）。字体颜色、背景高亮、分栏不做。
- **按段算**：段是 Bot 改内容、用户批注、标出谁写的、检查冲突的单位。列表的每一项、表格的每一行各算一段；
  引用、提示框、代码块、折叠块、标题、段落、分割线各算一段；嵌套的子项跟着上一级。
- **没改过的段一个字都不动**：切段只切行区间，不重排格式；编辑器只重新生成人真正改过的那几段。
- **先不做**：数据库（多维表）、同一段的实时多人协同（用版本号查冲突代替）、给外面的 Agent 用的 MCP 端点。

## 分几步

1. **按段编辑、版本历史、锁定（后端）**（已完成）：
   - `osa/blocks.py` 切段：服务器的切法是唯一标准；每段带着和上一段之间的 gap（紧挨着还是隔一个空行），`split(join(parts)) == parts`。
   - `osa/pagedoc.py`：每段的编号和作者存在 `pages.block_meta`（按位置对应切出来的段，带指纹，对不上就按指纹对齐重建）；
     按段修改，只在要改的段被别人先改过时才冲突，冲突时告诉调用方那几段现在的内容；整页重写时没变的段保留编号和作者；
     版本历史 `page_versions`（同一个人 10 分钟内接着改算一版，每页最多 50 版、4 MB）。
   - 工具：新加 `edit_page`；`read_page` 显示版本号和每段的编号 `⟦xxxx⟧`、能从某段接着读（Worker 读 7000 字以内）；
     `save_page` 别的 Bot 也能整页更新 markdown 页面，最近是别人改的要带 `version`；html 页面和小应用仍然只有建它的 Bot 能改；锁定的页面 Bot 只能读。
   - 接口：`GET/POST /api/pages/{id}/blocks`（冲突时 409）、`/versions`、`/versions/{id}`、`/versions/{id}/restore`，`PATCH` 能锁定；
     用户按段保存只广播 `page_changed`，不发 `pages_changed`（免得列表和页面卡片整个重拉）。
   - 搜索索引：没变的块沿用原来的向量。
2. **Notion 式块编辑器（前端）**（已完成）：Tiptap 3，懒加载（只在打开页面时加载）。每段单独解析；不认识的写法显示成“Markdown 原文”块，原样保留；
   自动保存只发改过的段，冲突时按段提示；Bot 改了实时合并进来，标出“正在编辑”；每段左边标出是哪个 Bot 写的；斜杠菜单、选中文字的格式菜单；
   页面地址 `/library/pages/<id>` 刷新不丢。
3. **批注叫醒负责的 Bot**（已完成）：在某一段上写批注，默认叫醒写这一段的 Bot（也能 @ 别的 Bot 或不叫），它改完在批注里回复；
   Bot 的批注不叫醒任何 Bot，免得来回停不下来。
4. **页面层级**（已完成）：子页面、移动、面包屑；删除父页面时子页面默认挪到上一级。
5. **网页上的版本历史**（已完成）：版本列表、看某一版、和现在对比（按段，段内按字）、回到某一版或只恢复一段。

## 怎么验收

- 每步：`uv run pytest -q` 通过；`python -m osa.i18n` 不缺翻译（改表结构时用临时的 `OSA_CONFIG` 跑，它会对真的数据库跑迁移）。
- 第 1 步：`tests/test_blocks.py`（每条切段规则、三条不变式）、`tests/test_pages.py`（各种修改、冲突、别的 Bot 整页更新、锁定、历史、读页面、接口）。
- 第 2–5 步：在数据副本上起服务，用 Playwright 逐项看：打开 Bot 写的页面不发任何保存请求；改一个词只发那一段，别的段逐字节不变；
  两个窗口改不同的段不冲突、改同一段出现冲突提示；断网再恢复能自动保存；手机宽度、深浅两种主题。
- 最后：拉一个群，让一个 Bot 写调研页、交接给另一个 Bot 接着改，用户批注一段，确认作者标记、版本历史、批注回复都对。
